# 古くなったナレッジを確かめ直す

`ika kb triage`・`ika kb stale` に出た、古くなっていそうなナレッジを確かめ直し、確かめた日を `ika kb review` で残す手順。残した日（フロントマターの `reviewed`）は、`date` と並べて遅いほうが「最後に確かめた日」になり、`stale`・`triage` はそれより後の変化だけを見る。週1回などで回すなら `schedule`・`/loop` から呼ぶ。

## いつやるか

- `ika kb triage` の「今週やること」に【README】【知見】【根拠】が出たとき
- ユーザーが「古い情報を確かめて」「stale を片付けて」と頼んだとき

## 手順

1. `ika kb triage`（プロダクトを絞るなら `-p <name>`）で上位を見て、確かめる項目を選ぶ。既定では上位3件まで。多いときは続きを聞く
2. 項目の種類ごとに、中身を確かめる
   - 【根拠】価格・競合などのノート: 公式の料金ページなど一次情報を開き、ノートの記述が今も正しいかを照らす。出典の URL（`source:`）があればそこから
   - 【README】: [project-sync スキル](../../project-sync/SKILL.md) の手順で、リポジトリの今の状態と照らす
   - 【知見】: 一覧のその後のノートを読み、知見が今も言えるかを見る（[distill.md](distill.md)）
3. 結果ごとに記録する
   - 今も正しい: `ika kb review <path>`。確かめた日が今日でなければ `--date YYYY-MM-DD`
   - 一部が変わった: 変わった事実を新しいノートに書き（[SKILL.md](../SKILL.md)）、根拠にしていた側（知見・決定・README）の本文とリンクを直す。古いノートは直さず、置き換えたら `review` を付けない。直した側は `ika kb review` でよい
   - もう使わない: 決定は `superseded`、要件書は `dropped` にする（ユーザーに確認してから）
4. 確かめられなかったもの（一次情報が取れない、判断が要る）には `review` を付けず、残した理由をユーザーに伝える。確かめずに日付だけ更新しない
5. `ika check` を通す。報告には、確かめた件数、`review` を付けたパス、直したもの、残したものを書く
