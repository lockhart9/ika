# 用途ごとの問いの型と出口

brainstorm の 1 で選んだ用途の節だけ読む。問いは 1 回に 1 つ、まだ触れていない角度から聞く。並びは目安で、上から順に全部聞く必要はない。

## 開発（機能・設計）

目的の例: 次の `cycle` のテーマを 1 つ選ぶ、機能の形を決める前に案を出し切る。

KB で先に見るもの: README の「課題・次の打ち手」、承認済みの要件書、決定（特に `rejected`）、技術の知見（`-d tech --type insight`）。

問いの型:

- 誰が、どの場面で困っているか。今はどう凌いでいるか
- 理想の状態は。それが叶ったら、何が見て分かるか
- どうすれば〜できるか（「〜」に困りごとを入れて言い換える）
- 逆に、やめる・削る・まとめるとしたら何か
- 制約（時間・費用・技術）を 1 つ外すなら何を作るか。最小の形なら何か
- 今ある機能・他のプロダクトで足りていないか。他のプロダクトでうまくいった形はあるか（`ika kb search <語> -l` で他のプロダクトも見る）
- 作ったら、何で良し悪しを確かめるか

絞る基準: 目的への効き、1 回の `cycle` で作り終えられる大きさか（大きければ分ける）、不確かさ（調べないと決められないことがあるか）、既存の決定と矛盾しないか。

出口:

- 選んだ 1 つ → `cycle` のテーマ。すぐ始めないなら README の「課題・次の打ち手」に足す（本人の了承を得て）
- 方式や範囲で迷う点 → `decide`
- 調べないと決められない点 → 市場調査の節の問いにして `cycle` の調査へ
- 残りの案 → ブレストのノートの「見送った案」（理由つき）。今後やるかもしれないものは README の「課題・次の打ち手」に「案」として足してよい

## 市場調査（調べる問いと仮説）

目的の例: 新しい事業・機能について、調べる問いを 3〜5 個に絞る。

KB で先に見るもの: `-d business` のノートと知見、データセット（`ika data ls`）、取り込んだ資料（`--type source`）、他のプロダクトで調べた市場・制度。KB で答えが出ている問いは、パスを添えて「調べ直さない」側に置く（古いものは日付を添え、変わりやすい事実だけ確かめ直す候補にする）。

問いの型（観点ごとに 1 つずつ）:

- 顧客・課題: 誰が、どの場面で困っているか。今どう凌いでいるか。いくら・どれだけの時間を使っているか
- 競合: 同じ課題を誰がどう解いているか。どのプランか。口コミの不満は何か
- 価格・収益: 払う人は誰か。相場はいくらか
- 制度・規約: 守るべき法令・ガイドライン・プラットフォームの規約はあるか
- 技術の前提: 使う API・ライブラリの制約や費用

問いが出たら仮説の形にする: 「〜は〜だろう。〜が分かったら外れ」。外れたときに何を変えるかも 1 行添える。

絞る基準: 答えで判断（作る・作らない・形・価格）が変わるか、KB でまだ答えが出ていないか、一次情報で確かめられるか。

出口:

- 絞った問いと仮説 → `cycle` の調査（要件まで進めるなら）か、`capture` スキルで調べた結果をノートにする
- KB で答えが出た問い → ブレストのノートにパスを残す

## タスク整理（洗い出しと次の行動）

目的の例: 今週やることを決める、頭の中の気になることを出し切って次の行動にする。

書き出しの手がかり（判断せずに全部出してもらうための材料。一度に全部見せず、本人の書き出しが止まったら 1 つずつ出す）:

- `ika project list` のプロダクトごとに「このプロダクトで気になっていることは」
- 各 README の「課題・次の打ち手」（`ika project show <name> --readme`）
- 承認済みでまだ作っていない要件書（`ika kb search --type spec --status approved -l`）
- KB の手入れ（`ika kb triage`: 未整理のノート・古い README や知見）と受信箱（`ika inbox ls`）
- KB の外のこと: 待っている返事、人との約束、期限のあるもの、ずっと気になっていること

1 つずつ分ける（GTD の clarify の考え方）:

- 行動が要るか。要らなければ「やめる」（捨てる）か「いつか」（今はやらないが残す）
- 要るなら、次の具体的な行動を 1 つ決める（「〜を考える」ではなく「〜に返信する」「〜を開いて読む」のような動作）。2 分で済むなら今やる
- 人や外の出来事を待っているなら「待ち」（誰の・何を）

区分: 次の行動／待ち／いつか／やめる。次の行動は、今日・今週にやるものに絞って見せる（一度にたくさん並べない）。

絞る基準: 期限、ほかの作業を止めているか、目的（今週何を進めたいか）への効き、手間。

出口:

- 次の行動の一覧を会話の中で返す。プロダクトに紐づかない個人のタスクは KB に残さない
- プロダクトに紐づく次の行動 → 本人の了承を得て、その README の「課題・次の打ち手」に足す
- KB の手入れ（`triage` に出たもの）→ `capture` スキルの手順（蒸留・確かめ直し・受信箱の整理）
- 作る・決めるに育ったもの → 開発の節の出口と同じ
