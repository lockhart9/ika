# data — 表形式データ

`IKA_HOME/data/` に置く（ika のリポジトリではない）。登録簿は CSV、溜めていくデータは SQLite。

- CSV は UTF-8・ヘッダ行あり・カンマ区切り。日付は `YYYY-MM-DD`
- JSON は1ファイル1データセット。配列かオブジェクトのどちらかに揃える
- 新しいデータセットを足したら、下の表に1行書く

| ファイル | 内容 | 列 |
|---|---|---|
| `projects.csv` | プロダクト登録簿（正本） | `name`（英小文字・ハイフン）, `path`（ローカルリポジトリ）, `url`（公開URL、無ければ空）, `status`（`active` / `paused` / `archived`）, `summary` |
| `domains.csv` | 領域登録簿（正本）。`kb/<name>/` と対応 | `name`（英小文字・ハイフン、`projects` は不可）, `summary` |

## データセット（`datasets.sqlite3`）

価格の履歴・計測値・ログのように、行が増え続けて集計して使うデータは `data/datasets.sqlite3` に溜める。
全データセットを1ファイルに持つ（1データセット = 1テーブル、定義は `_datasets` テーブル）。
人が直接読むものではないので、読み書きは `ika data`（と `ika serve`）を通す。`sqlite3` コマンドなどで直接書き換えない。

- 名前（データセット・列）は英小文字で始まり、英小文字・数字・アンダースコアだけ。SQL の識別子としてそのまま使う
- 型は `string` / `int` / `float` / `date`（`YYYY-MM-DD`）/ `bool` / `enum(a|b)`。既定は必須で、省略可は `?`（`url:string?`）
- `--key` は重複判定の列（必須の列だけ）。観測を取り直しても二重に入らないよう、日付・出所・対象をキーにする
- 追記は標準入力のヘッダ付き CSV。全行を検証してから1トランザクションで入れるので、不正な行があれば何も入らない
- 訂正は `ika data delete --where` で消して追記し直す。履歴は git（`IKA_HOME` の自動コミット）に残る
- `--domain`・`--project` で、どの領域・プロダクトのデータかを残す（登録済みの名前だけ）
- CSV は `ika data export` で書き出せる（移行・共有用）。`ika export --with-kb` のスナップショットには含めない
- DB はバイナリなので、git の差分は読めず、書き込みごとに履歴が増える。大きくなったら古い観測を `export` して整理する

データセットの一覧と定義は `ika data ls` / `ika data show <name>`。このファイルに表を書いて管理しない。
